# Canonical tax model

Canonical records use internal UUIDs. External IDs are evidence, not primary keys. Monetary values serialize as decimal strings with explicit cents. Blank, unknown, confirmed zero, and not applicable are distinct states. Arrays preserve repeated forms and rows, and stable child IDs replace array positions. Every normalized material field will retain source document, page/box, import batch, confidence, and correction lineage.

The 2025 root contract includes editable taxpayer/spouse identity and address profiles, an explicitly reviewed five-status filing profile, a versioned `standard_deduction_facts` block for claimable-taxpayer/Form 8615 screening and person-specific age/blindness facts, stable-ID dependent rows with separate dependent/CTC/ODC determinations, reviewed Schedule A amounts and limitation confirmations, strict 2025.1 Schedule C/E/F activity forms and an `advanced_federal` profile. That profile round-trips Form 6251 AMT facts, Form 8867 interviews/evidence, Form 1095-A/Form 8962 monthly reconciliation, Schedule 1/Form 8889 adjustments, payment ledgers and controlled-package preferences. Complete export serializes these fields and strict accepted/reviewed allocation rows back into the same schema accepted by import; imports materialize the same identity, source, return-profile, advanced-profile and activity records used by manual screens, with immutable Form 8867 certifications and activity/source revisions, atomic allocation sets and compensating rollback. Schema 1.4 adds typed `form_ssa_1099` and `form_rrb_1099` collections; import remains backward compatible with 1.0 through 1.3 payloads.

Unknown fields are preserved and produce review diagnostics. Capture support never implies calculation support.
