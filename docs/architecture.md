# Architecture

The application is a Next.js TypeScript system organized by tax domain. Browser components never own authoritative tax calculations. Services will authorize firm, assignment, client, and year scope server-side before reading or mutating data. PostgreSQL and Prisma provide transactional persistence; immutable revisions, calculation snapshots, artifacts, and audit events preserve reproducibility.

The implemented slices contain the workstation shell, a versioned JSON contract, transactional PostgreSQL migrations, synthetic seed data, append-only audit enforcement, administrator-managed client assignments, a Supabase password/TOTP identity adapter, explicit external-subject provisioning, MFA-backed hashed sessions, keyed pre-session authentication-attempt throttling, guarded and rate-limited sensitive mutations, persisted client/year/intake/import/source/mapping/review/calculation/output workflows, encrypted development source storage, durable output jobs, controlled internal form previews, reviewer workpapers, a deterministic 2025 calculation research package and firm-scoped release-closure evidence for gates, independent tax fixtures, infrastructure controls/readiness results, manual acceptance and output tie-outs. Production provider/ingress activation, managed object storage/scanning, independent tax-rule approval, production recovery evidence and release acceptance remain gated deployment work.

Release-closure evidence is stored as versioned PostgreSQL records. Server services derive comparison counts and SHA-256 identities, enforce role and firm scope, prevent preparer self-approval and append tax-value-free chained audit events. The application records decisions; it cannot substitute for the qualified human or organizational approvals required by the Master Plan.

Local PostgreSQL runs through `compose.yaml`. `scripts/migrate.ts` applies each SQL migration once inside its own transaction and records it in `_migrations`. Prisma remains the preferred application ORM, while the small server read repository uses parameterized `pg` queries until verified Prisma engines are available in the environment.

The selected production topology is a Hostinger Business Web Hosting managed Node.js Web App connected to GitHub, with Supabase providing PostgreSQL and authentication. Hostinger runs the optimized Next.js server and durable artifact worker through `scripts/hostinger-runtime.mjs`; deployment uses `npm run hostinger:build`, which applies migrations and fails closed on the production-readiness gate before building. This is intentionally different from BusAcTa.com's static FTP deployment because Nexus requires server APIs, secure sessions and background jobs.
