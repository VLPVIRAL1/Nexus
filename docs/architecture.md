# Architecture

The application is a Next.js TypeScript system organized by tax domain. Browser components never own authoritative tax calculations. Services will authorize firm, assignment, client, and year scope server-side before reading or mutating data. PostgreSQL and Prisma provide transactional persistence; immutable revisions, calculation snapshots, artifacts, and audit events preserve reproducibility.

The implemented slices contain the workstation shell, a versioned JSON contract, transactional PostgreSQL migrations, synthetic seed data, append-only audit enforcement, administrator-managed client assignments, a Supabase password/TOTP identity adapter, explicit external-subject provisioning, MFA-backed hashed sessions, keyed pre-session authentication-attempt throttling, guarded and rate-limited sensitive mutations, persisted client/year/intake/import/source/mapping/review/calculation/output workflows, encrypted development source storage, durable output jobs, controlled internal form previews, reviewer workpapers and a deterministic 2025 calculation research package. Production provider/ingress activation, managed object storage/scanning, independent tax-rule approval, production recovery evidence and release acceptance remain gated deployment work.

Local PostgreSQL runs through `compose.yaml`. `scripts/migrate.ts` applies each SQL migration once inside its own transaction and records it in `_migrations`. Prisma remains the preferred application ORM, while the small server read repository uses parameterized `pg` queries until verified Prisma engines are available in the environment.
